## 每周怎么过

以“周”为单位推进，不按自然日硬赶。每周 6 个学习日，内容可以挪动，但顺序尽量别乱。

| 时段 | 时长 | 做什么 |
| --- | --- | --- |
| 开场 | 20 分钟 | 打开上周代码跑一遍，看上周笔记的“卡点” |
| 学 | 40–60 分钟 | 读教程对应章节，**照着敲一遍**，不复制粘贴 |
| 练 | 90–100 分钟 | 做当周作业，先初级再中级，有余力做高级 |
| 收尾 | 20–30 分钟 | 改报错、写 3 行笔记、`git commit`、更新进度 |

每周第 7 天：补没做完的作业、重做一遍最卡的题、写周记（学会了什么/还不会什么/下周注意什么）。

**关于作业时长的说明**：作业里标的 35 / 65 / 45 分钟，是“已经看懂、写得顺利”时的**净写代码时间**，不含读教程、手敲示例、查报错、重做和写笔记。零基础实际通常要按 2–3 倍预留，所以一周 6 天正好填满 18 小时。如果第 3 天就写完了，不要提前开下一周，做“三件套”加深：不看教程重写一遍、补 3 组边界测试、给代码加注释并讲给自己听。

## 作业规则（三级）

每个 `homework/weekXX.md` 都分三级，**总时长控制在 3 小时内**：

- **初级（必做，约 40 分钟）**：当周知识点的最小验证，照着例子改，必须独立跑通。
- **中级（必做，约 60–70 分钟）**：组合运用，需要自己拆步骤，允许查教程和文档。
- **高级（挑战，约 40–50 分钟）**：没有现成答案，允许卡住；卡 20 分钟没思路就看提示，再不行就记录下来，下周复盘时再做。

提交要求（每周都一样）：

1. 代码放在 `code/weekXX/`，文件名见作业。
2. 运行通过后，在 `PROGRESS.md` 对应行勾选完成的级别。
3. 写 3–5 行 `notes/weekXX.md`：学会了什么、卡在哪里、怎么解决的。
4. Git 提交一次，信息格式：`week01: 完成初级和中级`；有高级就再提交一次。

## 学习原则

- **手打，不复制**：报错是最好的老师，复制会把这个环节省掉。
- **先跑通，再写好**：先让代码能跑，再拆分、改名、加注释。
- **卡 20 分钟再问**：先读报错最后一行 → 打印中间变量 → 搜索“报错原文 + python” → 再问人/AI。
- **每天提交**：Git 不是最后才学的工具，从第 1 周就用。
- **允许忘**：忘了就查 `notes/` 和自己的旧代码，这比背语法有用。
- **不追求学完所有章节**：菜鸟教程里的网络编程、MySQL、爬虫、AI 等，毕业后再按需学。
